Story Verification Loop

For developers using the ai-feature-verification Claude Code plugin: how a Jira story goes from "I built it" to "verified and approved". Claude runs each pass from start to finish without stopping. You read the report, act on it, and ask for another pass until the verdict is VERIFIED.

Once per machine

# 1 · install
claude plugin marketplace add kendallmark3/ai-feature-verification
claude plugin install ai-feature-verification@ai-feature-verification

# 2 · your Jira key (shell profile, never a committed file)
export JIRA_BASE_URL="https://your-site.atlassian.net"
export JIRA_EMAIL="the email of the account that made the token"
export JIRA_API_TOKEN="…"

Use Create API token, not the scoped kind. Then open a new terminal and start claude in your repo. The install guide has a one-line check that confirms Jira accepts the key.

What you say to Claude

WhenSay
Start"Verify PROJ-12"
Questions"Ask me the PROJ-12 questions"
After a fix"Verify PROJ-12 again"
Tests reviewed"Promote the PROJ-12 tests, I'm <name>"
Final run"Run PROJ-12 in pipeline mode"
Done"Post results to PROJ-12" · "Approve PROJ-12, I'm <name>"

Reading the verdict

VerdictWhat it meansWhat you do next
NOT VERIFIED A test failed: one of the new tests, or one of your existing regression tests.
  • Confirmed failure (reviewed test): the feature is wrong. Fix the code.
  • Suspected defect (unreviewed test): check the test first; it may be the test that's wrong.
  • Requirement ambiguity (open question on that criterion): answer the question; the "right" result isn't decided yet.
INCOMPLETE Nothing failed, but something couldn't be shown yet. The report lists why.
  • Open questions: answer them in chat, on the Answer: lines, or by fixing the criteria in Jira.
  • Tests still @ai-proposed: read them and promote them (Gate 2).
  • Interactive evidence only: commit, then do a pipeline run.
  • Not verifiable (e.g. "should be fast" with no number): give a number, or accept the risk.
VERIFIED Every criterion in scope has passing evidence from a pipeline run of reviewed tests on committed code. Post the results to the story if you want, and approve it (Gate 3). Approval is always a person's decision.
