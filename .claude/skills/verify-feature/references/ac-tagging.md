# Linking tests to acceptance criteria

The evidence step reads test names out of JUnit XML and looks for the AC ID there.
The story key is optional, but if a test name carries a *different* story key, the test is
ignored for this story, so tests from several stories can live in one suite.

Put both in the title:

| Framework | Example |
|---|---|
| Playwright / Jest / Vitest / Mocha | `test('SHOP-142 AC-3 rejects an unknown code with a message', ...)` |
| node:test | `test('SHOP-142 AC-2 SAVE10 takes 10% off', ...)` |
| pytest | `def test_shop142_ac2_save10_takes_ten_percent():` → also `@pytest.mark.parametrize(ids=["SHOP-142 AC-2"])`, or name the class `TestSHOP142_AC2` — the classname is searched too |
| JUnit 5 | `@DisplayName("SHOP-142 AC-2 SAVE10 takes 10% off")` |
| Cucumber | Scenario name `SHOP-142 AC-2 ...` |

One test may cover several ACs: `SHOP-142 AC-2 AC-5 applies SAVE10 on a phone`.

Tests without any AC ID are treated as existing regression tests: they still run, and a
failure among them makes the verdict NOT VERIFIED.

## Gate 2 markers

Every test file Claude creates gets a header comment. Claude writes generated tests in new
files and never edits a reviewed test file (one without the marker); the engine flags edits
to reviewed tests, and a pipeline run with such edits cannot verify.

```js
// @ai-proposed SHOP-142 — generated by the verify-feature skill.
```

`promote` turns it into `@approved-by <name> <date>`. The marker is searched for as plain
text, so any comment syntax works (`#`, `//`, `/* */`, `<!-- -->`).
